# 参考文献管理アプリ

学術論文における参考文献と本文中の引用を正しい形式で管理・生成するWebアプリケーションです。

## 機能

- **多種類の文献対応**: 日本語書籍、英語書籍、雑誌論文、翻訳書、楽譜、インターネット資料など
- **正確な引用形式**: 学術論文の標準的な引用形式に準拠
- **本文中の引用生成**: 割注形式の引用を自動生成
- **参考文献一覧生成**: 著者名順にソートされた参考文献一覧
- **データ管理**: ローカルストレージでの自動保存、JSON形式でのエクスポート・インポート
- **コピー機能**: ワンクリックでクリップボードにコピー
- **まとめて登録・編集**: 同じ団体名・著者名の読み仮名や、チェックした文献の出版社・発行年などをまとめて設定

## 対応する文献種別

1. **日本語書籍** - 単行本
2. **日本語雑誌論文** - 学術雑誌掲載論文
3. **日本語書籍所収論文** - 論文集や編著書の章
4. **英語書籍** - 洋書
5. **英語雑誌論文** - 海外学術雑誌
6. **英語書籍所収論文** - 洋書の章
7. **翻訳書** - 原書情報も含む翻訳文献
8. **辞事典項目** - 事典の項目
9. **楽譜（国内）** - 国内出版の楽譜
10. **楽譜（海外）** - 海外出版の楽譜
11. **インターネット資料** - ウェブサイト
12. **視聴覚資料** - CD、DVDなど

## 使用方法

### 開発環境での実行

1. 依存関係のインストール:
```bash
npm install
```

2. 開発サーバーの起動:
```bash
npm run dev
```

3. ブラウザで http://localhost:3000 にアクセス

### 本番環境用ビルド

```bash
npm run build
npm start
```

### テスト

参考文献・引用の出力やデータの読み込みの規則を確かめるテストです（追加のライブラリは使いません）。

```bash
npm test
```

### 公開（GitHub Pages）

GitHub Pages は `main` ブランチの `docs` フォルダを公開しています。

```bash
npm run deploy
```

ビルドして `docs` を作り直し、`docs` だけをコミットして `main` に送ります（作業中のほかのファイルは含めません）。

## 主な機能の使い方

### 1. 参考文献の追加
- 文献の種類を選択
- 必要な情報を入力（必須項目は*マーク付き）
- 「追加」ボタンをクリック

### 2. 本文中の引用
- 一覧の「引用」を押し、必要に応じて引用ページを入力
- 表示された引用の形を確かめて「コピー」（Enter でもコピー）

### 3. 参考文献一覧
- 一覧の左端で文献にチェックを入れる（「全て選択」「種類で一括選択」も使えます）
- 「参考文献一覧の出力」に、著者名順・発行年順で並んだ一覧が出るので、まとめてコピー

### 4. データの管理
- 自動保存: 入力内容は自動的にブラウザに保存（保存できなかったときは画面でお知らせします）
- ファイルに保存: JSONファイルとしてダウンロード（最後にバックアップした日と、そのあとの変更の有無を表示します）
- ファイルから読み込む: ない文献を追加し、同じ文献はより新しく直したほうの内容にします。読み込んだあとも「元に戻す」で戻せます
- 二重登録を整理: 同じ文献を2回登録したものを取り除きます

### 5. まとめて登録・編集
- 読み仮名をまとめて登録: 同じ団体名・著者名の読み仮名を、名前ごとに1回入力すれば、その名前が出てくるすべての文献に登録します。読み方が食い違っている名前も一覧で分かります
- チェックした文献をまとめて編集: 一覧でチェックした文献の出版社・団体名・発行年などを、変更内容を確かめてからまとめて同じ値にします（書名・URL など文献ごとに違う項目は対象外）
- どちらも保存後のお知らせの「元に戻す」で、変更前に戻せます
- 読み仮名の欄の「読みを調べる」で、[国立国会図書館の典拠データ（Web NDL Authorities）](https://id.ndl.go.jp/auth/ndla) から読みを調べられます。読みが1通りならそのまま入り、分かれるときは候補から選びます

## 技術仕様

- **フロントエンド**: React 18
- **バンドラー**: Webpack 5
- **スタイリング**: CSS3
- **データ保存**: LocalStorage + JSON
- **ID管理**: UUID v4
- **API**: 国立国会図書館API + CiNii API + Web NDL Authorities（読み仮名）

## 引用形式について

このアプリケーションは以下の学術的な引用形式に準拠しています：

- **本文中の引用**: 割注形式 `(著者　年:ページ)`
- **参考文献一覧**: 各文献種別に応じた詳細な書誌情報
- **翻訳書**: 原書情報も併記
- **多言語対応**: 日本語文献と英語文献の形式を適切に使い分け

## 外部データ連携（CiNii / NDL）

このアプリケーションは外部の書誌データソース（CiNii Research / 国立国会図書館など）からのメタデータ取得と、取得結果の自動マッピングに対応しています。主な仕様は以下の通りです。

- CiNii の opensearch 応答の正規化
	- CiNii Articles の opensearch JSON（items / @graph など）を正規化して内部モデルに変換します。
	- 検索結果から該当レコードの詳細（.json）を取得し、より詳細なメタデータをマッピングします。

- 著者情報の取り扱い
	- `dc:creator` を優先して抽出します。`@value` / `@id` などのオブジェクト表現も展開して文字列化します。
	- URL のみのエントリは著者表示ラベルとして扱わず、可能な限り人物名を表示します。

- DOI と NDL リンクの取り扱い
	- `dc:identifier` などから DOI と NDL（ndlsearch や id.ndl.go.jp の URL）を抽出します。
	- 表示用の `link` フィールドは NDL のレコード URL を優先的にセットします。DOI は別フィールドに保持し、モーダル上で DOI へのリンク（https://doi.org/）として表示されます。

- 自動マッピングと UI 挙動
	- 取得したメタデータを基にタイトル、雑誌名、出版社、巻号、ページ、出版年などをフォームへ自動入力します。ただし、取得データが空（空文字や空配列）の場合は既存の値を上書きしないよう安全にマージします。
	- Mapping モーダルでは著者を選択し、姓・名・読みを編集できます。日本語名に対する「前から N 文字で分割」機能を搭載しており、編集時に即時で反映されます。
	- 団体出版本では、著者（「文部科学省 編」の文部科学省など）を執筆団体に入れます。著者名に付いた「編」「[著]」などの役割の表示は取り除きます。

## 注意事項 / 開発時のヒント

- 外部サービスはブラウザから直接呼び出しています（サーバーはありません）。アクセスが集中して断られたときは、表示された時間だけ問い合わせを控えます。
- 公開版のページは、このアプリと3つの外部サービス（国立国会図書館サーチ・CiNii Research・Web NDL Authorities）以外とは通信しない設定（Content-Security-Policy）にしています。外部サービスを増やすときは `webpack.config.js` の `connect-src` に追加してください。

## テーマ（配色）

- テーマは `src/utils/themes.js` に定義しています。画面右上のテーマのボタンから、系統ごとに並んだ配色のカードを見比べて選びます。
- 「基本」の8種類は [Tailwind CSS v3 の標準カラーパレット](https://v3.tailwindcss.com/docs/customizing-colors) から色を選び、各色の横にパレット上の色名（例: `indigo-200`）を書いています。
- それ以外の117種類は [色彩101®「4色の配色パターン」](https://shikisai101.com/color-scheme/colors/4/) の配色をもとにしています。配色名は出典のままで、メインの色の色味で系統に分けています。4色から文字・ボタン・背景の色を自動で作り、黒に近い文字が読めないほど濃い色は、色味を保ったまま明るくしています。配色を追加するときは `PALETTES` に1行足してください。
- すべてのテーマが WCAG 2.1 AA（文字 4.5:1、入力欄の枠線 3:1）を満たすようにしています。テーマを追加・変更したら、次のコマンドで確認してください。

```bash
node scripts/check-theme-contrast.mjs
```
